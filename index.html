Ansible Agentless Architecture

Ansible connects to target machines using standard SSH (for Linux/Unix) or WinRM/PSRP (for Windows), executes small python/powershell scripts (modules) on the target, and removes them when finished. No agent daemon needs to be installed on target nodes!

Key Fundamental Concepts

🔄 Idempotency
Executing a playbook 1 time or 100 times yields the exact same state without unintended side effects. If configuration is already correct, Ansible makes 0 changes (returns ok instead of changed).
📝 Declarative Syntax
You specify what state you want your systems to be in (e.g. state: present, state: started), rather than scripting imperatively how to install or configure it step-by-step.
🔍 Fact Gathering
Before running tasks, Ansible automatically runs the setup module to collect target system facts (IP addresses, OS version, CPU count, disk space) into the ansible_facts variable.
⚡ Order of Precedence (ansible.cfg)
1. ANSIBLE_CONFIG (environment variable)
2. ./ansible.cfg (current working directory)
3. ~/.ansible.cfg (user's home directory)
4. /etc/ansible/ansible.cfg (system default)

Variable Precedence Hierarchy (Top to Bottom)

Ansible has 22 levels of variable precedence. Higher levels override lower levels!

1. Extra Vars (-e "var=value") - HIGHEST
2. Task vars (only inside task)
3. Block vars
4. Role and include vars
5. Set_fact / Registered vars
6. Play vars / vars_files
7. Host facts (ansible_facts)
8. host_vars/ directory files
9. group_vars/ directory files
10. Role defaults (roles/x/defaults/main.yml) - LOWEST

Standard Ansible Role Directory Structure

Roles provide a structured, reusable way to organize tasks, handlers, variables, defaults, templates, and files.

roles/webserver/
├── defaults/
│   └── main.yml         # Low-priority default variables
├── vars/
│   └── main.yml         # High-priority role variables
├── tasks/
│   └── main.yml         # Main task list executed by role
├── handlers/
│   └── main.yml         # Handlers notified by tasks
├── templates/
│   └── nginx.conf.j2    # Jinja2 template files
├── files/
│   └── index.html       # Static files to copy
└── meta/
    └── main.yml         # Role metadata & dependencies

Ansible Galaxy Commands Cheat Sheet

ansible-galaxy role init roles/my_new_role
Initializes standard folder structure for a new role.
ansible-galaxy collection install community.general
Installs Ansible collection containing additional community modules.
ansible-galaxy install -r requirements.yml
Installs all roles and collections declared in a requirements file.

Ansible Vault (Encrypting Secrets)

Ansible Vault allows you to encrypt password strings, API keys, or entire YAML secret files so they can be safely stored in version control (Git).

Interactive Vault Text Encrypter / Decrypter

Click Encrypt to generate Vault header & ciphertext

Ansible Vault CLI Commands

ansible-vault create group_vars/all/vault.yml
Creates a new encrypted file.
ansible-vault encrypt group_vars/all/secrets.yml
Encrypts an existing file in-place.
ansible-vault edit group_vars/all/secrets.yml
Decrypts temporary file in editor, then re-encrypts upon save.
ansible-playbook site.yml --ask-vault-pass
Runs playbook asking interactively for vault password.
ansible-playbook site.yml --vault-password-file ~/.vault_pass
Passes vault password non-interactively for CI/CD automation.
